## 2026-07-28: dcp__read "\undefined" ENOENT at the Pillar B session start, diagnosed and fixed

The Pillar B session's first dcp__read (`{"path": "packages/hooks/src/handlers.ts"}`) failed with `ENOENT ... open '<worktree>\undefined'` and the model fell back to raw Read per the fail-open rule. Reproduced from the session transcript and root-caused as a real defect in the MCP serve path, not transient or environmental:

- The tool schema names the argument `file_path`, but the call arrived with `path` — the name dcp__search advertises, an easy confusion the schema layer did not reject.
- `toolRead` in packages/mcp/src/server.ts did `String(args['file_path'])`, and `String(undefined)` is the literal string `"undefined"`, so `readFileSync` resolved a file literally named `undefined` against the cwd and threw the misleading ENOENT.
- Fix: toolRead now accepts `path` as an alias for `file_path`, and a call with neither returns `dcp__read failed: missing required argument file_path (string)` instead of an ENOENT on a phantom path. Two new tests in packages/mcp/test/server.test.ts cover the alias serving the file and the missing-argument message. Suite 284 green, lint clean.
